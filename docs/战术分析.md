# 无界攻击链推演（第一性原理复盘）

记录本环境实战中推演/验证过的非常规打法，以及为什么成、为什么败。重点是**判断依据**，不是脚本。

## 1. 我们真正控制了什么

| 控制点 | 来源 | 能做的事 |
|---|---|---|
| 网关 root | 中兴 G1610 webFac 工厂后门 → telnet root | DNS 覆写、DNAT、DHCP 选项、全量流量可见 |
| L2 路径 | ARP 欺骗（双向） | 让目标流量改道，绕过目标对"我们 IP"的封锁 |
| 明文 HTTP | 透明代理 + 401 注入 | 逼 NTLM 认证、替换下载、伪造更新应答 |
| DNS | 全域覆写 | 指向自己、伪造更新/门户、屏蔽真实上游 |
| 已控设备 | Epson 打印机管理员 | 纸面钓鱼（9100 RAW 打印）、固件升级面 |

结论：**控制流量 ≠ 看见内容**。TLS 之后一切明文收割都失效，路由器只是管道。

## 2. 已验证失败的方向（避免重复投入）

| 方案 | 结果 | 根因 |
|---|---|---|
| network-wide DNS 劫持后截 cookie | 失败 | 目标流量 TLS 占比 100%（HSTS 阻断降级），明文 HTTP 只剩 NCSI/更新类探测 |
| NTLMv1 降级（远程触发） | 失败 | Win10/11 默认 `LmCompatibilityLevel=3`，远程改不了注册表；挑战位压不动 |
| MS17-010 / SMBGhost | 失败 | 目标为 LTSC 19044/Win11 26100，补丁已含 |
| 中继 .5 的 MSA 到 A3 | 部分成功但无权限 | MSA 非 A3 本地账户，映射为 Guest |
| 匿名 RPC 枚举 .10 | 失败 | Win11 26100 匿名 samr/lsarpc 全 `LOGON_FAILURE` |
| PetitPotam/PrinterBug（无凭据） | 失败 | 无凭据时 MS-EFSR/MS-RPRN 全 `ACCESS_DENIED`；有 spooler 但需认证 |
| CVE 直打（2025-33073 / 47981 / 2026-72936） | 失败 | 均需低权限凭据或需赢竞态，无可用公开 PoC |
| 13,000 模板 nuclei 扫内网网关 | 0 命中 | 设备固件为电信定制，模板库无对应指纹 |

## 3. 历次踩坑（工程性教训）

1. **NTLM 中继的连接粘性**：透明代理若每请求新建上游连接，type1/type3 落在不同连接上 → 中继必败。必须 `(peer,host)` 粘性上游 + `Content-Length` 收满。
2. **ntlmrelayx 目标池被烧**：一次失败即把目标移出列表。必须 `--keep-relaying`，否则先来的失败认证会让后来的成功认证无处可去。
3. **端口争抢**：ntlmrelayx 默认绑 135/445/WCF 9389/WinRM 5985，与 Responder 冲突时线程崩并带崩主进程。必须 `--no-rpc-server --no-wcf-server --no-winrm-server`，或让 Responder `SMB=Off` 只做毒化。
4. **ntlmrelayx 交互台随 stdin 关闭自杀**：`nohup ... &` 会退出，需 `sleep infinity | ntlmrelayx` 保活。
5. **劫持页/载荷的编码陷阱**：中文经 telnet 管道传输会损坏，必须 base64 或 scp 落地。
6. **载荷完整性**：曾出现 16MB 木马被写成 152MB（传输事故），后用哈希逐字节校验才发现——**任何投递前必须校验 sha256**。
7. **procd jail 里的 rpcd**：定制 LuCI 的会话由 jail 内 rpcd 建，kill 后无人拉起 → 登录成功也签不出 cookie → 表现为"登进去又弹回"。修复只需重启 jail，不需要改任何密码。
8. **测试污染目标状态**：反复用脚本登录会写 `loginip`，导致真实用户会话被互斥顶掉——**验证要用一次性会话并退出**。

## 4. 高价值但未完成的方向

1. **强制认证（coerce）+ 反射**：A3 的 `Administrator` 自认证反射回自身是可成功的（自己认证自己），前提是 `.scf`/401 触发。链路已修好，等触发。
2. **网关 DHCP option 252 强推 WPAD**：不依赖客户端"自动检测"开关，续租即下发，覆盖面比 ARP 欺骗更广。
3. **固件离线解密**：G1610 的 `db_user_cfg.xml` 为 type-4 AES，密钥材料（`/etc/hardcode` + `libhardcode.so` 的 key 派生）已全部取回，属纯离线 Ghidra 活，做完即得 WiFi/PPPoE/全部后台明文。
4. **SMB 客户端 RCE**：当恶意 SMB 服务器比客户端漏洞本身更难——需要赢竞态的漏洞（如 CVE-2026-72936）工程成本高，若后续出现稳定 PoC 应优先复用（目标持续连我们的假 File 服务器）。

## 5. 方法论

- **先算收益，再动手**：能用凭据解决的绝不打漏洞；能用配置解决的绝不写 exp。
- **排除项也是成果**：每次"打不通"都要写清根因，避免下一个人重走。
- **一切可回滚**：所有规则/改配置都记录原值 + 回滚命令，收尾即恢复。
- **校验优先于投递**：哈希、尺寸、Content-Type 三查后再发。
